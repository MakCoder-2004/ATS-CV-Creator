# Implemented workflows

This page describes the current Pi-powered source code and the [installed 0.4.0 validation](validation/pi-sdk-installed-0.4.0.md). Earlier 0.3.0 validation reports remain historical evidence for the former OpenRouter release. This is a reference for product changes, not a description of the browser-only prototype or a plan for future job discovery. The [architecture map](architecture.md) identifies the code that owns each boundary.

## Prepare a tailored CV

The Tailor CV page moves through five stages in [`WorkbenchStart.tsx`](../src/renderer/WorkbenchStart.tsx) and [`WorkbenchStageLayout.tsx`](../src/renderer/WorkbenchStageLayout.tsx).

1. **Job posting.** Select a saved job or add one in Saved jobs. The accepted working posting, not a separate captured source snapshot, is the input for assessment.
2. **Outgoing data.** Inspect the minimized posting and profile facts. Acknowledge the privacy notice and authorize the reviewed outgoing data for one run and its selected Pi model and thinking level. Authorization starts posting analysis for that run; an analysis failure offers an explicit retry. Neither an older cache entry nor a prior approval authorizes a new run.
3. **Generate.** Read the analyzed required and preferred qualifications, tools, responsibilities, and keywords. Choose a one- or two-page target, then explicitly generate. The application selects profile evidence and asks the model for structured, cited wording. One long saved fact can still supply a section when its source exceeds that section's estimated output length. The app measures actual PDF page fit later. Generation progress reflects recorded work. A received malformed response saves no model wording and cannot be resumed; review outgoing data before explicitly starting another run. A structured response with invalid citations is discarded and leaves an empty, blocked draft for source-backed manual correction. A Pi run interrupted with an uncertain result needs an explicit recovery decision; an older OpenRouter run cannot resume under Pi and needs a new preview, consent, analysis, and generation.
4. **Review evidence.** Inspect the document and its cited sources. The inspector groups Sources, New skills, Job match, and Checks & options. Posting-only skill suggestions are marked **Not in your profile**. Confirm or remove each suggestion before approval. Confirmation applies to this CV only and does not establish past work with the tool. Edit wording or add and remove records using selected evidence, run factual checks, measure the actual PDF page fit, resolve findings, and acknowledge the current wording before approval. A proposed page cut changes the draft only after acceptance and clears the prior checks and approval.
5. **Export.** Review the actual compiled PDF. Export the approved content as a selectable PDF or editable DOCX. The DOCX uses the same canonical content but can paginate differently. A draft edit, changed source, or changed posting can require renewed review before export.

The PDF uses Letter paper and Lato, with Education, Experience, Projects, and grouped Technical Skills. Education places school and dates on the first row, degree and any supported GPA/CGPA on the second; repeated metadata in generated wording is omitted from bullets without changing saved profile facts. It has no summary, target headline, or Certificates section. Profile facts remain in the profile even when a section is omitted from a particular CV. The model does not write LaTeX. Evidence and deterministic checks support review but do not prove that a statement is true or that a CV will pass an ATS.

## Save and refresh a job posting

[`SavedJobs.tsx`](../src/renderer/SavedJobs.tsx) supports manual entry and a link flow for named Lever detail pages. Link intake runs a bounded fetch, presents extracted fields and conflicts for correction, and saves only after the person accepts the preview. A refresh compares new source wording against the accepted working posting. The user decides whether to keep each correction or take updated source details. Source snapshots and accepted posting revisions remain separate in [`jobs.ts`](../src/shared/jobs.ts). Unsupported sites use manual entry; fetching a page is not consent to send its text through Pi.

Saved jobs offers a checkbox in each Posting cell, a select-all toolbar below the heading for the displayed rows, a selection count, and an individual Delete action beside Edit and Open posting in Next action. The confirmation lists the current job titles, companies, and draft counts. Cancel keeps the selection. A busy job must be stopped in Tailor CV, and a stale preview must be reviewed again. The backend rechecks the selection and removes the selected jobs and related local CV work atomically. Profile facts and exported files remain untouched. After commit, the table and sidebar shortcuts refresh; deleting the active job returns Tailor CV to its choose-a-posting state without starting another model run. Older backups can still restore deleted jobs. New consents record the job ID, but old superseded runs without a surviving job link can leave unattributable consent and model-history records in the workspace and new backups. Deletion preserves those records rather than assigning an unproven owner. The focused UI and preparation checks are recorded in the [D2 implementation evidence](validation/spec-72-implementation.md).

A saved draft can still target an earlier posting revision. The review workspace labels it as earlier wording. The user can inspect a new outbound preview and either generate a new draft or renew review of existing wording against the current posting. Approval for an earlier posting does not automatically cover the new revision.

## Maintain a profile

[`ProfileEditor.tsx`](../src/renderer/ProfileEditor.tsx) edits contact information, skills, education, certificates, summary, languages, and other facts. Experience and projects use their own record editors. The profile records facts for future drafts; CV-only edits do not silently rewrite it. Manual draft-record operations can explicitly target the CV alone or both the CV and profile, with source history retained. A new factual assertion requires current saved evidence; declaring a wording-only change is not a truth guarantee.

PDF and DOCX profile uploads produce temporary proposals, not automatic profile mutations. The user selects changes to apply. For section-based text PDFs, local import can recognize stacked contact, education, work, project, skill and certificate passages, including links tied to the same PDF text line. A stacked work record whose employment or training kind is uncertain stays unselected until the user chooses a record type; unmatched links and uncertain text stay in review rather than becoming facts. Optional Pi structuring for both PDF and DOCX has a separate minimized-text preview, frozen provider, model, thinking level, and one-run consent before any provider request. Its output remains proposals until explicit review and application. Profile JSON export and import are a separate exchange and replacement flow. These paths are implemented in [`src/main/profile-pdf-import-ipc.ts`](../src/main/profile-pdf-import-ipc.ts), [`src/main/profile-docx-import-ipc.ts`](../src/main/profile-docx-import-ipc.ts), and [`src/main/profile-exchange-ipc.ts`](../src/main/profile-exchange-ipc.ts).

## Manage settings and backups

Settings stores appearance, one exact Pi provider/model and thinking level, and the optional faithfulness preference. Choose an available model and sign in with Pi outside CV Tailor. Settings has no in-app provider key or local model-usage budgets. The approved upgrade deletes only CV Tailor's old encrypted OpenRouter key row, not Pi's credentials. Each new model run needs an outgoing-data preview and consent, including when saved analysis is reused. [`PiSettings.tsx`](../src/renderer/PiSettings.tsx) and [`workbench.ts`](../src/main/workbench.ts) own these controls.

[`WorkspaceBackup.tsx`](../src/renderer/WorkspaceBackup.tsx) exports the local workspace. Restore previews the replacement, validates known records, makes a safety copy, and then reopens the workspace. A backup excludes credentials. Restoring an older backup drops OpenRouter model and budget settings; restored consent cannot authorize new Pi work. Saved drafts and source history remain readable. The application's backup path is the supported restore operation; a raw SQLite file copy is not.

## What is not shipped

The documents under [research on later features](research/ai-job-search-adoption-plan.md) include possible job discovery, cover letters, application tracking, interview aids, and other later features. They are research and proposals, not installed features. [`prototypes/cv-tailor-ui/`](../prototypes/cv-tailor-ui/) contains browser-only design evidence.
