# Implemented workflows

This page describes the current Pi-powered source code and the [installed 0.4.0 validation](validation/pi-sdk-installed-0.4.0.md). Earlier 0.3.0 validation reports remain historical evidence for the former OpenRouter release. This is a reference for product changes, not a description of the browser-only prototype or a plan for future job discovery. The [architecture map](architecture.md) identifies the code that owns each boundary.

## Prepare a tailored CV

The Tailor CV page moves through five stages in [`WorkbenchStart.tsx`](../src/renderer/WorkbenchStart.tsx) and [`WorkbenchStageLayout.tsx`](../src/renderer/WorkbenchStageLayout.tsx).

1. **Job posting.** Select a saved job or add one in Saved jobs. The accepted working posting, not a separate captured source snapshot, is the input for assessment.
2. **Outgoing data.** Inspect the minimized posting and profile facts. Acknowledge the privacy notice and authorize the reviewed outgoing data for one run and its selected Pi model and thinking level. Authorization starts posting analysis for that run; an analysis failure offers an explicit retry. Neither an older cache entry nor a prior approval authorizes a new run.
3. **Generate.** Read the analyzed required and preferred qualifications, tools, responsibilities, and keywords. Choose a one- or two-page target, then explicitly generate. The application selects profile evidence and asks the model for structured, cited wording. New experience and project descriptions are one paragraph, with no more than 60 words. Existing drafts without explicit format metadata keep their released bullet layout. One long saved fact can still supply a section when its source exceeds that section's estimated output length. The app measures actual PDF page fit later. Generation progress reflects recorded work. A received malformed response saves no model wording and cannot be resumed; review outgoing data before explicitly starting another run. A structured response with invalid citations is discarded and leaves an empty, blocked draft for source-backed manual correction. A current-format interrupted run with an uncertain request needs an explicit retry decision. Earlier prompt-format recovery snapshots, including Pi snapshot version 2, cannot resume under old consent; they remain readable and need a fresh preview, consent, analysis, and generation.
4. **Review evidence.** Inspect the document and its cited sources. The inspector groups Sources, New skills, Job match, and Checks & options. Posting-only skill suggestions are marked **Not in your profile**. Confirm or remove each suggestion before approval. Confirmation applies to this CV only and does not establish past work with the tool. Edit wording or add and remove records using selected evidence, run factual checks, measure the actual PDF page fit, resolve findings, and acknowledge the current wording before approval. A proposed page cut changes the draft only after acceptance and clears the prior checks and approval.
5. **Export.** Review the actual compiled PDF. Export the approved content as a selectable PDF or editable DOCX. The DOCX uses the same canonical content but can paginate differently. A draft edit, changed source, or changed posting can require renewed review before export.

The PDF uses Letter paper and Lato, with Education, Experience, Projects, and grouped Technical Skills. New and explicitly regenerated experience or project descriptions render as paragraphs in review, PDF, and DOCX. The PDF leaves readable leading between heading metadata and prose. Project links remain clickable and right-aligned in the same heading row; paragraph-format project headings use a bounded wrapping link column so long repository labels do not collide with titles or technologies. Older drafts without format metadata retain bullets, including unchanged siblings grouped under the same role or project as a newly regenerated paragraph. Their canonical content hashes remain unchanged. Education places school and dates on the first row, degree and any supported GPA/CGPA on the second; repeated metadata in generated wording is omitted from education descriptions without changing saved profile facts. It has no summary, target headline, or Certificates section. Profile facts remain in the profile even when a section is omitted from a particular CV. The model does not write LaTeX. Evidence and deterministic checks support review but do not prove that a statement is true or that a CV will pass an ATS.

## Save and refresh a job posting

[`SavedJobs.tsx`](../src/renderer/SavedJobs.tsx) supports manual entry and a link flow for named Lever detail pages. Link intake runs a bounded fetch, presents extracted fields and conflicts for correction, and saves only after the person accepts the preview. A refresh compares new source wording against the accepted working posting. The user decides whether to keep each correction or take updated source details. Source snapshots and accepted posting revisions remain separate in [`jobs.ts`](../src/shared/jobs.ts). Existing Lever source snapshots and user-entered manual postings retain their save and refresh paths. A bounded public read for LinkedIn, Indeed or another non-Lever job URL may show exact-role text in a temporary preview or incomplete findings in a research notice; the server refuses new fetched non-Lever saves and refreshes with “Review temporarily or paste text manually.” A completed direct run transfers once by token to volatile research without rereading the URL, including full direct text. Full previews state that the source is temporary and was not saved to jobs or backups; captured non-Lever posting data is discarded by a bounded 15-minute timer measured from the original Fetch posting start, including network delay, if not transferred, or immediately and entirely upon transfer. The main-process read returns that original deadline with settled non-Lever previews and research notices; a late renderer response cannot restart the clock. The separate volatile research session owns the cloned run for at most 15 minutes; an eager deadline timer aborts and removes it even when the app stays idle. Its outgoing analysis preview/result has an independent eager 15-minute deadline. The renderer clears open research, outgoing analysis and full non-Lever preview copies at their deadlines, including when resuming a suspended window, and discards them on cancellation, link change or closing intake. Fetch posting again is an explicit recovery action. Manual text and Lever save workflows are unaffected. The renderer presents full non-Lever text read-only with no Save job, Refresh or edit controls. A complete or partial selected source can be reviewed in temporary research, then inspected in a separate exact Outgoing data preview. The notice distinguishes the displayed user message from Pi's separate structured system instruction. A fresh run-specific authorization and explicit Start analysis action precede the Pi request. The source text, snippets, consent and result are not saved to jobs, analysis cache, drafts, recovery or backups; temporary analysis cannot generate or export a CV. This development behavior has not been validated in an installed app. Historical non-Lever jobs restored from older backups stay readable and backed up but cannot refresh their fetched source; neither fetch nor transfer creates a new saved job or authorization to send source text through Pi. See [direct intake validation and open gates](validation/universal-direct-intake.md).

Saved jobs offers a checkbox in each Posting cell, a select-all toolbar below the heading for the displayed rows, a selection count, and an individual Delete action beside Edit and Open posting in Next action. The confirmation lists the current job titles, companies, and draft counts. Cancel keeps the selection. A busy job must be stopped in Tailor CV, and a stale preview must be reviewed again. Cancelling releases posting edits immediately, but deletion and workspace backup or restore stay blocked until every outstanding provider response for that job settles. The backend rechecks the selection and removes the selected jobs and related local CV work atomically. Profile facts and exported files remain untouched. After commit, the table and sidebar shortcuts refresh; deleting the active job returns Tailor CV to its choose-a-posting state without starting another model run. Older backups can still restore deleted jobs. New consents record the job ID, but old superseded runs without a surviving job link can leave unattributable consent and model-history records in the workspace and new backups. Deletion preserves those records rather than assigning an unproven owner. The focused UI and preparation checks are recorded in the [D2 implementation evidence](validation/spec-72-implementation.md).

A saved draft can still target an earlier posting revision. The review workspace labels it as earlier wording. The user can inspect a new outbound preview and either generate a new draft or renew review of existing wording against the current posting. Approval for an earlier posting does not automatically cover the new revision.

## Maintain a profile

[`ProfileEditor.tsx`](../src/renderer/ProfileEditor.tsx) edits contact information, skills, education, certificates, summary, languages, and other facts. Experience and projects use their own record editors. The profile records facts for future drafts; CV-only edits do not silently rewrite it. Manual draft-record operations can explicitly target the CV alone or both the CV and profile, with source history retained. Editing an existing experience or project record keeps its paragraph format when the selected draft item has one, in either scope. Manual descriptions can exceed the 60-word limit for model-generated paragraphs, but the edit clears prior fit and approval and still requires review. Older items without format metadata keep their bullet layout. A new factual assertion requires current saved evidence; declaring a wording-only change is not a truth guarantee.

PDF and DOCX uploads create temporary profile proposals; they do not change saved facts. The existing importer reads each document locally and keeps the local proposal route available. AI-assisted extraction is the primary presentation, with **Continue locally** as a clear alternative. Before any provider request, the app shows the minimized readable source text, selected Pi provider, model and thinking level. The person must authorize one request for that preview. The app sends no binary document, saved profile, unrelated file or credential. It gives the model complete application-issued page and passage references, including text the local mapper did not classify. The app accepts only exact cited source passages, assigns proposal identities itself and leaves uncertain role types or unrepresented text unresolved for review. It rejects AI output that drops explicitly supported local facts rather than replacing the review with fewer facts. A new role can be classified as Employment or Training only when its own cited parent passage explicitly labels the kind and contains both its title and organization. A PDF line or DOCX paragraph can contain more than one role heading; its authentic source locator does not establish which role owns each field. AI proposals citing such a unit are rejected without replacing the local review, where the original text remains inspectable. A heuristic local role kind can be corrected only when the same parent passage supplies a clear contrary label, including an `Internship — organization` role heading. Incidental description words and another role's label do not establish its kind. Source-backed skill categories stay unchanged unless the skill's own cited passage has one unambiguous heading for a different supported category. Multiple skill headings in one source unit cannot authorize a category change or a new skill classification; unchanged locally sourced categories remain proposals for review. Certificate and project links need their own cited URL or attached hyperlink. AI output remains editable proposals. The person reviews add, update and skip choices before atomic application. A stale profile leaves the temporary review available for an explicit refresh of merge choices; corrections to record kind preserve the original source passage without treating other manual wording changes as source support. Profile JSON export and import remain a separate exchange and replacement flow. These paths are implemented in [`src/main/profile-pdf-import-ipc.ts`](../src/main/profile-pdf-import-ipc.ts), [`src/main/profile-docx-import-ipc.ts`](../src/main/profile-docx-import-ipc.ts), [`src/shared/profile-source-evidence.ts`](../src/shared/profile-source-evidence.ts), [`src/shared/profile-ai-structuring.ts`](../src/shared/profile-ai-structuring.ts), and [`src/main/profile-exchange-ipc.ts`](../src/main/profile-exchange-ipc.ts).

## Manage settings and backups

Settings stores appearance, one exact Pi provider/model and thinking level. Choose an available model and sign in with Pi outside CV Tailor. The Pi model card includes external sign-in guidance; there is no separate Provider sign-in or Optional faithfulness review card, in-app Pi provider key or local model-usage budget. Separately, the adjacent Tavily card can store a user-provided search key using device encryption outside the workspace and its backups. A saved key is masked by default; the person can explicitly Reveal and Hide it, Copy it via the main-process clipboard, replace it through a separate field, or confirm removal of the local encrypted copy. Status, ordinary Settings and backups never contain plaintext. Hide, model changes and leaving Settings clear the renderer's revealed value; copying leaves it on the system clipboard until replaced. Removing the local copy does not revoke the provider key in Tavily. Saving, revealing, copying, removing or checking key status makes no search request. Search queries may disclose public role metadata or a verified employer domain to Tavily and other search-index providers. Saved jobs offers a temporary review after complete or incomplete non-Lever public reads. Choosing indexed search for incomplete direct findings makes a separate Tavily request; full direct wording needs no indexed search. Neither saving a key nor reviewing findings starts Pi analysis. Inspecting Outgoing data, authorizing that precise run and explicitly starting analysis are separate decisions. The approved upgrade deletes CV Tailor's old encrypted OpenRouter key row and the retired faithfulness setting, not Pi's credentials. Older `semantic-unsupported` findings stay attached to saved drafts; paused runs from the earlier review contract require a fresh outgoing-data review and authorization. Each new model run needs an outgoing-data preview and consent, including when saved analysis is reused. [`PiSettings.tsx`](../src/renderer/PiSettings.tsx), [`TavilyKeyCard.tsx`](../src/renderer/TavilyKeyCard.tsx), [`research-search-settings-ipc.ts`](../src/main/research-search-settings-ipc.ts) and [`workbench.ts`](../src/main/workbench.ts) own these controls.

[`WorkspaceBackup.tsx`](../src/renderer/WorkspaceBackup.tsx) exports the local workspace. Restore previews the replacement, validates known records, makes a safety copy, and then reopens the workspace. A backup excludes credentials. Restoring an older backup drops OpenRouter model and budget settings; restored consent cannot authorize new Pi work. Saved drafts and source history remain readable. A pre-Pi generation run remains visible as unable to resume; any unsettled provider attempt count remains visible without permitting replay. The application's backup path is the supported restore operation; a raw SQLite file copy is not.
