# Volatile reviewed research analysis — bounded core (not shipped)

This branch adds an independent main-process-only controller and shared schemas. It is **not connected** to renderer, preload, trusted IPC, Saved jobs, persistence, or generation. No real provider or search request was made in this validation.

## Integration contract

`createVolatileResearchAnalysis({ getAppHeldRun, getAppHeldReview, getPiSelection, piRuntime, now?, maxRuns? })` returns `preview(runId)`, `consent(token)`, `start(token)`, `read(token)`, `cancel(token)`, `decline(token)`, and `discard(token)`. These are main-process methods, **not renderer input contracts**. Integrator must supply actual immutable app-held `JobResearchRun` and review lookups; `verifyReviewedJobResearch` recalculates accepted IDs/hash against the held run. Never pass client-provided run/review values as the held copy. Trusted IPC must validate its tokens, arguments, and ownership separately.

`preview` returns `outgoingText`, provider/model/effort, scope and disclosure. Render the complete outgoingText **verbatim**, without redaction or truncation, and the notice before accepting consent. This exact string is the user-message prompt passed to `completePiTask`; the Pi helper separately sends a generated JSON-schema system message. There are no hidden role excerpts, profile or employer-context facts in that message. Only accepted exact-role finding text, IDs, source URLs, capture dates and unknowns are frozen; partial evidence remains provisional. The model returns JSON requirements with accepted finding-ID references; invalid or foreign IDs yield no published result. Semantic truth of metrics/tenure and accuracy of model wording cannot be mechanically guaranteed: results are explicitly marked `humanReviewRequired` and must be inspected before any other use.

Consent is explicit once per research run. Preview, consent and model selection cause **zero** physical Pi calls. `start` reserves the token synchronously, rechecks run/review/selection immediately before dispatch, and calls existing tool-free `completePiTask` once (`tools: []`, `maxRetries: 0`). No malformed-response repair, provider fallback or replay. A dispatched failed/cancelled request can still reach the provider and be charged; progress counts physical dispatch attempts as 0/1 and marks failed dispatch as uncertain. Cancellation aborts and discards late results. Entries expire within 15 minutes and capacity is capped at 12 by default (configurable 1–32); discard and app close lose memory. An app-held run has at most one live preview; after expiry or explicit discard, re-entry requires a **new** preview and fresh consent, never a cache hit or authorization reuse. Neither this module nor these schemas call workbench, SQLite, cache, backup or checkpoints. No durable saved job or CV generation authorization is created.

## Focused checks / remaining gates

Run `./node_modules/.bin/vitest run tests/research-volatile-analysis.test.ts --maxWorkers=1 --no-cache` and `./node_modules/.bin/tsc --noEmit --pretty false` against the read-only main dependency junction. Synthetic fake-runtime tests check outgoing data minimization, per-run consent, one dispatch, no retries, invalid citations, cancellation, stale model/evidence/review, expiry and duplicate start. Real Pi, installed app, UI/IPC integration, source rights, provenance quality, semantic verification, and approval for generation from provisional evidence remain **open**. Existing Saved jobs and draft behavior are untouched by this isolated module. Do not persist rights-sensitive research until retention, redistribution and backup rights are cleared.
