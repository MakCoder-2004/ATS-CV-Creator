## Chosen evidence contract

The existing deterministic mapper remains the local first pass. A separate `ProfileSourceEvidenceDocument` records the captured document hash, format, exact page text and ordered source passages. Each passage has an application-issued page-and-position locator, exact offsets, source text and only the hyperlinks attached to that passage. PDF units follow extracted line order. DOCX units follow paragraph order. Long passages are split at exact offsets; source-unit overflow refuses AI preparation rather than dropping text.

The outgoing preview shows readable minimized source text and page/passage locators rather than raw JSON or random internal IDs. The model can cite only supplied locators. It cannot provide page values, quotations, fields or persistent proposal IDs. The app resolves each citation against the frozen evidence, creates exact proposal source records, validates each proposed value and issues persistent identities itself. The validator requires every source passage to be either cited or retained as unresolved. Unknown role kinds stay unresolved. A nested fact must follow its role or project evidence without an intervening unassigned source passage, and it must precede the next proposed parent. A hyperlink without a paragraph or line anchor stays unresolved. Ambiguous associations remain for correction or skip.

The alternative was to add more deterministic recognition rules and classify the resulting passages before AI. That would preserve the local mapper's current ownership model, but it would still hide readable text from new role proposals. The evidence document was selected because it makes the extraction source, position, hyperlinks and exact support explicit without broadening local parsing or trusting model-created evidence. The cost is a strict output-coverage requirement and conservative rejection when parent order is ambiguous.

## U2 independent-review fixes and development evidence

The reviewed AI result now keeps explicitly source-backed local contact, role, project, skill and link facts. If a proposed result omits one, the app rejects the entire AI result and keeps local proposals. Unlabeled narrative text that the local mapper mistakes for a skill does not become a mandatory fact. PDF and DOCX tests exercise the frozen multi-field fixtures, not a skill-only shortcut. The development-only scripted response now includes all supported fields needed by these fixtures. It is a deterministic test transport, not a provider-quality measurement.

Certificate links require an exact URL in their own cited passage or an attached hyperlink on that passage. New Employment and Training kinds require an explicit label on that role's cited source unit. Ambiguous kinds remain unresolved. Model-generated or wrong-parent citations remain rejected. Redaction keeps date ranges distinct from phone numbers, and the temporary transport schema accepts placeholders only until local restoration and final strict profile validation.

Stale PDF and DOCX reviews retain their token and edits until explicit discard or expiry. Refresh reloads the baseline and resets merge choices for review rather than silently carrying them forward. Selecting a kind for an unresolved local role retains the immutable parent passage if its other fields are unchanged. Manual changes to the title, organization, dates or description do not inherit parent field-support claims. Backup validation now accepts the importer’s existing education institution/description and certificate link field names only when the corresponding saved entry contains that property. The earlier backup allowance counted three request-history tables. The follow-up narrowed `profile-import:` UUID identities to the two tables the importer actually writes, `analysis_attempts` and `provider_attempt_outcomes`. Posting `outbound_consents` and recovery extensions require ordinary UUID run identities; malformed import identities are rejected. These changes closed backup refusals exposed by source-history and dispatched-attempt assertions.
