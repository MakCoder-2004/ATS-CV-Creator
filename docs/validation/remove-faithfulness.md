# Optional faithfulness removal. Development verification

The Settings Pi model block retains a single sign-in instruction. The separate Provider sign-in and Optional faithfulness review blocks and their named setting API are gone. Generation still sends the authorized posting analysis and cited draft/repair prompts, but no separate semantic comparison prompt. A restored or existing `faithfulness-check=true` settings row is deleted on restore or workspace open. This does not clear existing `semantic-unsupported` draft findings or change an approved older draft.

New generation recovery snapshots use version 4 without a faithfulness flag. Earlier versions 1, 2 and 3 remain parseable for backups. None can resume under its earlier consent; the person must review outgoing data and authorize a new run. Existing draft and request history remain inspectable. Backup restore revokes earlier consent and cancels paused work as before.

Focused development verification passed 44 tests across six affected Vitest files under Electron Node, `tsc --noEmit`, `electron-vite build` and `node scripts/check-doc-links.cjs`. These checks use synthetic data and scripted transport only. `tests/source-linked-generation.test.ts` seeds a formerly enabled settings row, reopens, generates a cited draft and confirms there is no second comparison request. It also verifies historical findings remain blocking after edits and reopen. `tests/generation-recovery.test.ts` checks legacy version-3 true snapshots cannot dispatch and remain backup-readable. `tests/workspace-backup.test.ts` restores a backup with the old true row and verifies it is absent after reopen. `tests/electron/pi-settings.spec.ts` asserts Settings card absence in isolated Electron storage. One focused development Electron attempt did not reach the page because `electron.launch` timed out after 20 seconds through the read-only shared dependency junction. The UI assertion is not yet runtime-proven in this worktree. This is not an installed-app or real-provider acceptance record.
