# Issue 94 link intake and authorization baseline

**Baseline:** branch `issue-94-baseline`, commit `e359660` (2026-10-26). This is a source-and-test baseline, not an installed-app observation. No production code changed.

## Verdict

**Acceptance is not met.** The repository contains focused synthetic API and Electron tests that can reproduce key paths, but this worktree has neither `node_modules/.bin/vitest` nor `node_modules/electron/dist/electron.exe`. The UI could not be launched here. Therefore visible confirmation and screen counts are **INCONCLUSIVE**, not measured. Existing checked-in Electron test expectations are cited as test evidence, not results from this run. No live credentials, actual postings or CV data were used.

The relevant data shapes are a saved `JobRecord`, volatile `JobResearchRun` / `ReviewedJobResearch`, per-run `OutboundConsentPreview`, and temporary profile import proposals. A preview, an authorization, a progress state, review of results, and each physical provider dispatch are different events.

## Evidence limits

Source inspection establishes the current control flow, not a screen-level count or provider execution. In particular, generation dispatch count is data-dependent; Tavily may spend a credit and may perform a verification GET; and a failed provider request can have uncertain processing/charges. The next baseline pass needs a runnable Electron build and synthetic fixtures, then should record visible controls and actual fixture dispatch logs independently. No live key or real CV is needed.
