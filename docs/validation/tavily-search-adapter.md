# Tavily free-only search adapter pilot

This unit adds no Settings field, network activity on key save/status/remove, renderer access, persisted search findings, live provider test, account creation, or paid authorization. The user must create and confirm their own Researcher account and provide a key through a future Settings integration. Search data stays separate from Pi/model credentials and profile data. No API key was available or used in validation.

## Integration boundary

`src/main/research-search-credentials.ts` exports `createResearchSearchCredentials`, `DeviceEncryption`, `ResearchSearchCredentials`, and `SearchCredentialStatus`. Main must pass Electron `safeStorage` as the injected encryption implementation, the verified physical workspace directory, and a **separate** credentials directory. Exact integration call (not wired on this branch): `createResearchSearchCredentials({ encryption: safeStorage, credentialsDirectory: defaultResearchCredentialDirectory(app.getPath('appData'), app.getPath('userData')), workspaceDirectory: app.getPath('userData') })` when the SQLite workspace is directly in userData. If the actual workspace path differs, pass its verified real path instead; also verify that this separate credentials root is outside all workspace and backup roots before use. The helper chooses `appData/CV Tailor Search Credentials`, a sibling of ordinary `appData/CV Tailor` userData, and rejects overlap (including aliases); it does **not** place credentials in `userData`, SQLite, or workspace backup. The constructor rejects credentials directory under or over the workspace, including existing symlink/junction aliases, and operations recheck aliases. The service writes only encrypted bytes to `tavily-key.dpapi` in that separate directory, using a private temporary file, sync, then atomic rename. Mode `0600` is not proof of Windows ACL isolation; Windows DPAPI via Electron safeStorage protects the bytes. Encryption unavailable means no write or plaintext fallback. Status exposes only `configured`, `storageAvailable`, and a fixed message. Removal deletes the local key, not the provider-side credential. Errors never include a key or provider response. `withKey` is strictly a privileged main-process callback and must never be wired to IPC or to a renderer. Encrypting bytes is delegated to Windows Electron safeStorage and is not tested on a live installation in this unit.

`src/main/tavily-search.ts` exports `createTavilyResearchSession`, `PublicJobSearch`, `TavilySearchResult`, `TavilyLink`, and `TavilyTransport` for injected Node tests. The future orchestrator must check that metadata is public, that the posting identity or employer domain is verified, and that the user explicitly initiated a fresh run before constructing a session. Typed input accepts only role title, posting host, optional canonical role ID, or a verified employer domain and optional title. It cannot accept arbitrary provider options. It must never pass profile/CV text, Pi keys, private URLs, or contact identifiers disguised as a title. This adapter rejects obvious email/control data, but cannot itself prove a title is publicly sourced. Candidate result URLs are untrusted leads, not verified posting sources. The adapter rejects non-HTTPS, explicit ports, credentials, IP literals (including loopback/private), local/reserved hostnames and ambiguous syntax without resolving or visiting candidate hosts. A future fetcher must revalidate **every** URL and redirect against public DNS **all answers** (reject mixed/public-private sets), pin the public address while verifying hostname TLS, and check exact role and employer identity against the selected posting before treating text as evidence. Never call a snippet a verified posting. Render candidate URLs, titles and snippets as inert text rather than active HTML. Source normalization, user review and rights clearance remain required.

A session reserves at most three searches synchronously, serializes preflight and search, and sends at most five links per query. Each search performs a bounded authenticated `GET /usage` preflight, then exactly one `POST /search` when the response unambiguously reports `Researcher`, plan limit `1000`, zero pay-as-you-go usage and limit, and at least one credit remaining on both account and key. Unknown or altered plan metadata is refused. All requests use fixed HTTPS `api.tavily.com`, public DNS validation, pinned IP with hostname TLS verification, no redirects, a 12-second per-request deadline, a 256 KiB response limit, no retries and sanitized errors: `TavilySearchError.code` distinguishes `authentication` (401/403), `billing` (402), `quota` (429/432), and `plan_unverified` (missing/unknown plan metadata, non-free or exhausted preflight). Other transport and malformed-response errors remain generic. Only these fixed fields are sent: `search_depth: basic`, `auto_parameters: false`, `include_answer: false`, `include_raw_content: false`, `max_results: 5`, `chunks_per_source: 1`, `topic: general`, `include_usage: true`. It returns only bounded HTTPS URL candidates, titles, snippets, credit count and request ID; it drops the AI answer, raw page content and the rest of the provider payload. A malformed response, DNS pivot, wrong credit count, timeout or cancellation produces no evidence. The API key is supplied only as the Authorization bearer header to the fixed Tavily host.

## Published facts and gate limits

The [Search API reference](https://docs.tavily.com/documentation/api-reference/endpoint/search) describes `POST /search`, basic search at one credit, request fields, response usage and request ID. The [Usage API reference](https://docs.tavily.com/documentation/api-reference/endpoint/usage) documents `GET /usage` with `account.current_plan`, `plan_usage`, `plan_limit`, `paygo_usage`, `paygo_limit`, and key usage/limit. The documentation shows `Bootstrap` as an example but does not enumerate permitted `current_plan` strings or guarantee that a free account returns exactly `Researcher` and zero paygo limit. This adapter therefore fails closed if actual free-account responses differ. **Pilot remains blocked** until the real user confirms actual plan and paygo metadata in their own Tavily account; do not infer plan from key prefix or relax the free-only gate. Do not loosen the check to infer a tier from key prefix. The [pricing page](https://www.tavily.com/pricing) lists free Researcher at 1,000 monthly credits with no card and says requests stop after exhaustion unless upgraded; paid plans and pay-as-you-go can bill normally. This adapter cannot independently guarantee the account remains on a free tier between the preflight and POST, or account-wide concurrency from other clients. Integration must not offer paid use implicitly. The app never upgrades or subscribes.

The [privacy policy](https://www.tavily.com/privacy) says queries can be retained, used to improve service and sent to other search-index providers. [Terms](https://www.tavily.com/terms) do not grant blanket rights to store third-party full-page content. Before persisting anything in jobs or backups, obtain permission for brief attributed excerpts and the relevant direct-source text. Do not persist full provider responses. Keep company context distinct from role requirements and require explicit outgoing-data review before any separate Pi analysis.

## Verification

Settings source renders configured-but-unavailable status as a locally stored encrypted key that cannot be used for searches now, while keeping local removal available; it does not expose key text. The focused Electron Settings regression asserts cancellation focus restoration after the confirmation controls unmount and preservation of an in-progress replacement key. An earlier runtime check was inconclusive because it launched a stale `out/main/index.js` without rebuilding the renderer bundle. The Settings Electron tests now create separate `workspace` and `appdata` siblings inside one temporary root, pass isolated `APPDATA` and test-only path overrides, and assert Electron's actual main-process `appData` and `userData` paths before any synthetic key save. The key test asserts that ciphertext is written under only the isolated appData sibling, without touching the user's normal credential directory. The alternate Pi model reopen test also uses its own isolated appData sibling. Packaged builds ignore these test-only overrides. After rebuilding the main, preload, and renderer bundles, the bounded Settings key/focus and Pi model reopen Electron tests both passed (2/2); the key test uses synthetic text only, confirms encrypted bytes in the isolated sibling, and never checks or removes real user credentials.

Run targeted Node-only mocks, with this worktree's isolated `.audit/vitest.tavily.config.mts`, using `./node_modules/.bin/vitest run --config .audit/vitest.tavily.config.mts --maxWorkers=1`. Typecheck with `./node_modules/.bin/tsc --noEmit --pretty false`. The above development Electron tests and an electron-vite build were run for the isolated Settings change; no installed Electron, real user key, Tavily request, native rebuild, or full suite was run. The `.audit` test config and cache are private to this worktree and not committed.

Model the Domain made a session own the three-dispatch counter and serialization, rather than spreading accounting across callers. Boundary Discipline put strict provider, DNS, encryption, and JSON checks at main-process boundaries; downstream orchestration still owns source identity and user consent.
