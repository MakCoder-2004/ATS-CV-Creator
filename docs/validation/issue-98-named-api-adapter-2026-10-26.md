# Issue 98 named API adapter — NOT ENABLED

This focused unit adds an inert main-process adapter for exact named Lever and Greenhouse public detail APIs. It has no IPC or renderer route, source-policy change, live network check, persistence, provider/Tavily/settings changes, or enabled product workflow. Results are temporary typed attempt/candidate objects; integration and promotion remain outside this unit.

The adapter constructs only the documented detail endpoint from the validated #97 reference, requires trusted main-process source-specific personal-local eligibility, checks DNS public addresses, pins HTTPS to the checked address, disables redirects, and bounds response/body/text/TTL. Mismatched identity and ambiguous hosted URLs fail closed. Lever `descriptionPlain`, `lists`, and `additionalPlain` are combined; list/additional HTML is parsed in a resource-limited worker with a hard deadline, bounded input/complexity/tree traversal, malformed structures and unclosed unsafe elements refused. When only Lever's `additional` HTML exists, it is extracted rather than silently dropped. Greenhouse `content` is likewise converted in the bounded worker to text; its optional custom-domain `absolute_url` is neither fetched nor treated as identity evidence. For Greenhouse, the selected board is bound to the exact constructed API route and the response's posting ID; the candidate does not claim the API independently returned a board token. No test contacted either provider.

Focused deterministic tests are in `tests/named-posting-api.test.ts`. This unit does not establish source reuse/retention rights or supersede #104's pause. It is not enabled pending #99/#101 gates, broader cancellation/deadline and hostile-response tests, and review of source-specific identity/expiry semantics.
