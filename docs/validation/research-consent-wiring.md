# Temporary research analysis consent wiring (2026-10-25)

Issue #88's reviewed, rights-pending role findings use a **separate volatile analysis-only path**. The six named `WorkbenchAPI`/preload methods (`previewResearchAnalysis(researchToken)`, `consentResearchAnalysis(token, accepted)`, `startResearchAnalysis(token)`, `readResearchAnalysis(token)`, `cancelResearchAnalysis(token)`, `discardResearchAnalysis(token)`) have matching trusted-main-frame IPC handlers with strict argument and response schemas. The renderer must call them in that order after the user reviews and accepts exact role findings. The research token is an app-issued handle, not a renderer-supplied run, review, hash, provider result, or job ID. Unreviewed, expired, cancelled, and replaced research refuses preview or dispatch.

Preview freezes the accepted role-only findings, source URLs and capture times, selected identity, unknowns, full/provisional scope, and Pi provider/model/thinking level. Display the **entire `outgoingText` and `notice`** alongside selection before consent: this is the exact user message, while Pi's SDK sends a *separate JSON-schema system message*. No candidate profile, CV, private key, search query, or employer-background finding is sent. The preview must not imply that snippets constitute a full posting. After explicit consent, `start` rechecks app-held evidence, review, selected Pi settings, and model-setting changes immediately before physical transport. Provider failures/late responses/foreign citations cannot publish, and there is no automatic retry. Cancellation after dispatch cannot undo provider receipt or charges. `read` is the only result path; show citations, unknowns and provisional scope, require human review, and do **not** offer Generate CV for provisional analysis. Discard/expiry/quit remove this memory-only state; deleting/cancelling research invalidates dispatch and result publication. A new app launch starts without analyses.

Neither the volatile controller nor these handlers call workbench save-job, analysis cache, SQLite, or workspace backup. Existing saved-job analysis/generation stays separate and unchanged. The renderer integration is owned by another worker and is not claimed as shipped here; real Electron and provider runs remain open integration gates.

Focused verification: `tsc --noEmit`; `vitest run tests/research-volatile-analysis.test.ts tests/research-consented-analysis-ipc.test.ts --maxWorkers=1 --cache=false`; `npm run build`. Tests use synthetic role evidence and Pi callbacks, not real Tavily/Pi traffic or an Electron GUI. Static handler/preload assertions supplement the connected in-memory test but do not replace a renderer-through-Electron smoke.
