# Issue 98: temporary named Greenhouse preview

**Status: reviewed development implementation; no named posting can be saved.** The visible Saved jobs link intake can request one exact public Greenhouse Job Board API posting only after the person checks a personal-local, per-run opt-in. It shows title, employer, board/post ID, captured time, source-updated time or Unknown, and complete read-only text marked **NOT SAVED**. Lever (including documented EU hosts), LinkedIn and Indeed remain paused. Generic Greenhouse direct reads are now gated before DNS so they cannot bypass the named opt-in; unrelated generic direct/manual paths and historical jobs remain unchanged.

The main process issues a random temporary token and owns the abort controller **before** starting a named API read. The candidate exists only in a bounded in-memory session. Cancel, URL edit, opt-in withdrawal, close, unmount and ten-minute expiry invalidate the renderer generation and abort/delete the main session; late replies cannot repaint discarded text. IPC replies are schema-checked; the renderer sees detached copies. The fixed named API adapter uses pinned public HTTPS/DNS, no redirects, bounded JSON and worker-based HTML extraction. No named Save, backup, CV, model analysis or source snapshot mutation is reachable from this preview. Other installations start with this per-run opt-in unchecked. This is the trusted main process, **not** an AppContainer isolation claim.

**Focused verification:** Six synthetic main-session tests, typecheck, build, docs links and diff checks passed. One isolated development-Electron test used a fixed in-app fake Greenhouse response and non-network generic transport seam through the visible Saved jobs UI/public preload. It verified opt-in, one request under a disabled repeated-click action, URL-edit stale-result suppression, visible source text/update time/NOT SAVED state, no saved jobs, and generic Greenhouse/EU Lever pause without requests. The first Electron run did not reach UI ready because the shared preview schema imported `node:crypto` into the sandboxed preload; browser-safe Zod schemas were split from main-only acceptance hashing and a build confirmed the preload has no Node-only require. The next run reached the preview but a hard-coded ISO-date assertion failed under local date formatting; the assertion now checks the renderer's formatted date. A final targeted run passed. No real source URL, provider credential, packaged app or installed executable was exercised.
