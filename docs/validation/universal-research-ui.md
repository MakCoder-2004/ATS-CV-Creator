# Public job-link research UI (wave 2A)

Saved jobs retains the approved three-column row layout, manual paste, historical source snapshots and Lever's existing full editable/review/save path. Full non-Lever direct captures (`linkedin-public-html-v1` and `public-jsonld-v1`) instead show exact read-only wording with title, company, source URL and capture time, plus the temporary/not-saved notice; upstream notices that imply saving are replaced with “Review this temporary source before analysis; nothing is saved.” No edit, save or refresh control is rendered. **Review temporary findings** transfers the original fetch token to `startJobResearchFromPosting` once, with no direct GET or Tavily search. Changing the source URL invalidates the capture. The link entry accepts public job links; `Fetch posting` is the sole initial request. An incomplete direct read presents a research notice rather than a saveable posting. The person must then explicitly start temporary exact-role research, separately choose Tavily indexed search after seeing the query/privacy/credit notice, select only role findings, acknowledge partial evidence and review those IDs. Employer context is read-only and cannot become a role requirement. Original source URLs remain inert text; the selected canonical URL can be opened through `openPostingSource`.

This UI is intentionally **not a shipped end-to-end analysis flow**: the optional `onReviewedResearch(token, reviewed)` handoff is ready for a parent to navigate to Outgoing data, but `main.tsx` does not yet supply it and the consent-bound provisional analysis API is not connected. The renderer explicitly says nothing was saved or analyzed and offers the manual full-posting route. For an incomplete direct read, temporary research transfers the already captured fetch token once and makes no duplicate GET. After transfer, cancellation marks that captured read as consumed; the notice says “Captured read was used. Fetch posting again to restart.” and cannot fall back to a fresh research read. Only the explicit **Fetch posting again** action starts a new fetch. Switching to pasted text cancels any still-transferable posting token and invalidates late fetch callbacks. Temporary research sessions are cancelled on UI unmount/cancel; main expires them after 15 minutes. Search disclosure shows the constructed metadata-only query, possible 1 credit / up to 5 results, and sharing with Tavily/index providers plus the network address. On the Stage B candidate branch, Settings now provides encrypted device-only Tavily key setup. This dated wave 2A report predates that integration; see [Stage B assembly](universal-research-stage-b.md). If the person explicitly chooses indexed search, Tavily receives only the displayed query; only after a matching indexed result may the app directly check the selected public page again. The UI discloses these conditions. The first captured direct read is transferred without duplication; only an exact indexed candidate can trigger a conditional public reread. No provider account/key or real search request was configured during development.

Verification for temporary full-preview UI and lifecycle behavior: `npm run typecheck` and `npx vitest run tests/job-research-ui.test.ts --maxWorkers=1`; static rendering asserts the full temporary action and absence of Save/Refresh, and tests check the child render condition retains the token identity, saved-preview wording is replaced, and the API helper transfers the token without URL start. No DOM environment is installed, so the child is not exercised in a mounted interaction test. These checks do not exercise interactive full-preview DOM behavior. The focused test covers captured-token transfer, cancellation requiring a refetch before another start, and cancellation of an untransferred token when switching to manual capture. No packaged app, native rebuild, live Tavily request, real Pi run, or build is part of this fix. A visible Electron intake-to-outgoing-consent-to-provisional-analysis test remains the wave 2B integration gate; do not mark issue #88 shipped on this UI alone.
