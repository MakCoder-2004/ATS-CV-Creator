# Public job-link research UI (wave 2A)

Saved jobs retains the approved three-column row layout, manual paste, historical source snapshots and the existing full direct-posting preview/save path. The link entry now accepts public job links; `Fetch posting` is the sole initial request. An incomplete direct read presents a research notice rather than a saveable posting. The person must then explicitly start temporary exact-role research, separately choose Tavily indexed search after seeing the query/privacy/credit notice, select only role findings, acknowledge partial evidence and review those IDs. Employer context is read-only and cannot become a role requirement. Original source URLs remain inert text; the selected canonical URL can be opened through `openPostingSource`.

This UI is intentionally **not a shipped end-to-end analysis flow**: the optional `onReviewedResearch(token, reviewed)` handoff is ready for a parent to navigate to Outgoing data, but `main.tsx` does not yet supply it and the consent-bound provisional analysis API is not connected. The renderer explicitly says nothing was saved or analyzed and offers the manual full-posting route. Temporary sessions are cancelled on UI unmount/cancel; main expires them after 15 minutes. No provider account/key or real search request was configured during development.

Verification: `npm run typecheck`, `npx vitest run tests/job-research-ui.test.ts --maxWorkers=1` and `npm run build` (where dependencies and backend permit). No packaged app, native rebuild, live Tavily request or real Pi run is part of this wave. A visible Electron intake-to-outgoing-consent-to-provisional-analysis test remains the wave 2B integration gate; do not mark issue #88 shipped on this UI alone.
