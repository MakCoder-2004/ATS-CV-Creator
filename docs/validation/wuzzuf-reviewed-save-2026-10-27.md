## Implemented boundary

- The generic Wuzzuf public direct-read/research path remains separate and non-saveable. To enable only the maintainer's Windows installation, create `%APPDATA%/CV Tailor Personal Local Policy/wuzzuf-personal-local.json` manually with `{"version":1,"wuzzufPersonalLocalEnabled":true,"acknowledgedNoticeVersion":1,"installationFingerprint":"<fingerprint>"}`. Calculate the fingerprint using `node scripts/wuzzuf-install-fingerprint.cjs "<physical-install-root>"`. Use the directory containing `CV Tailor.exe` for packaged Windows builds, or the unpacked app root containing `package.json` for development (the root above `out/main`). The script prints only the normalized path's SHA-256 fingerprint, never the path. The file stores only the SHA-256 fingerprint, not the path. In-place upgrades retain authorization; moving/copying the app to another root does not. Restart CV Tailor after creating or removing the file. The app never creates it. Remove it or invalidate its contents to disable. It is outside userData/workspace exports and is not carried in workspace backups. This local opt-in is not publisher permission or legal advice.
- Main pins every resolved address only when all are public, sends minimal headers with no browser/model/profile credentials, refuses all redirects, limits the response to 2 MiB, applies a 15-second deadline and two-second worker parse budget, and cancels/discards superseded or closed attempts. It does not retry or follow linked pages.
- An identity-less `JobPosting` candidate needs one unique canonical URL equal to the selected posting URL, exactly one structured role, independently matching visible title and employer, and a complete description present in visible page text. Static visibility checks reject hidden/aria-hidden/inert/title/company evidence, hidden ancestors, known hidden classes, and inline display/visibility/opacity/content-visibility hiding. Conflicts, missing evidence, login/restricted pages, and incomplete/teaser text fail closed. Static parsing cannot evaluate arbitrary external CSS/media queries; this residual limitation is documented, and the UI explicitly requires the human to inspect the original page and compare its visible title, employer and complete text before Save.
- Preview text stays in an expiring main-held session until exact-role/full-text review and a one-time Save grant. Saving is transactional, detects duplicates, and retains the captured source snapshot separately from editable working wording. Save does not authorize model dispatch. Existing backups remain unchanged and may retain accepted text after live deletion.
