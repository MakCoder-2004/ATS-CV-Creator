# Installed Windows 0.1.0 — local replacement and SQLite reopen

The 0.1.0 installer was downloaded from the public GitHub prerelease, verified against its published SHA-256 `ef8d655d87764c4ea34abfd77ac5a97a4e10e0dd582029bd4c8bf4cb7531fb28`, and installed as a per-user NSIS app on the user's confirmed Windows test machine. This is separate from the earlier [build-only candidate record](release-0.1.0-candidate.md).

Before replacement, the installed 0.6.2 executable and per-user uninstall registration were identified. The user's real workspace was backed up twice outside the application directory: an application-exported version-3 JSON backup, plus a consistent SQLite online backup with `PRAGMA quick_check=ok`. Neither backup is in Git. The user explicitly requested deletion of the old app data after retaining these recoverable copies. The 0.6.2 uninstaller exited 0; its registry entry, executable and Start Menu shortcut were absent. Only the old app's roaming `cv-tailor` user-data directory was removed, not exports elsewhere or Pi credentials. A temporary copy of the old installation used for rollback was deleted after the new build passed verification.

The downloaded 0.1.0 installer exited 0. `%LOCALAPPDATA%\Programs\CV Tailor\CV Tailor.exe` reports version 0.1.0; its installed `app.asar`, Electron-native SQLite addon and LaTeX toolchain manifest match the verified unpacked build byte-for-byte by SHA-256. The per-user uninstall registration and Start Menu shortcut point to the new installation. The installer did not launch the app or recreate the deleted regular workspace.

A separate **genuine installed-app** smoke used a temporary `--user-data-dir`. Before writing, Electron's physical `app.getPath('userData')` was checked against that isolated directory and `app.isPackaged` and `app.getVersion()` were verified. Through the visible UI and public preload bridge, a synthetic job and appearance change were saved. After closing and reopening the installed executable, the saved job and appearance remained; native `workbench.sqlite` existed in the isolated directory. The isolated fixture was removed after the check. This proves installed startup, native SQLite write and reopen on this machine—not a real provider run or installed PDF/DOCX export.

The 0.1.0 installer remains unsigned and is a version-number reset below 0.6.2; automatic/in-place upgrade behavior is not claimed. Real Pi login/provider quality, installed page-fit/PDF/DOCX flows, and public redistribution notice completeness remain unverified. Keep the prior JSON/SQLite recovery copies private because they contain personal career data.
