# Application architecture

CV Tailor is an Electron desktop application for keeping a local profile of career facts, saving job postings, and producing a reviewed tailored CV. The installed app runs on Windows. Its renderer is React and TypeScript; the main process owns the database, network requests, model requests, native dialogs, and file operations. The [project glossary](../GLOSSARY.md) defines the terms used here. This page describes current source code. The installed 0.4.0 Pi workflows, native SQLite reopen and real provider checks are recorded in the [release validation](validation/pi-sdk-installed-0.4.0.md).

## Stack and repository layout

The [locked npm package](../package.json) and [Electron Vite config](../electron.vite.config.ts) define the build. This table names packages that the current application uses, rather than every transitive dependency.

| Concern | Current choice |
| --- | --- |
| Desktop and build | Electron 39, TypeScript 5, Electron Vite 5, Vite 7, and an NSIS Windows installer through electron-builder. |
| Interface | React 19, CSS and Tailwind 4, Radix Select and Popover controls, Lucide icons, and bundled Manrope and Sora variable fonts. The exported PDF instead uses Lato. |
| Records and validation | `better-sqlite3` in the main process; Zod schemas shared across processes. |
| Model work | Pi SDK `ModelRuntime.completeSimple()`, LangGraph state graph, and a SQLite checkpoint saver. |
| Documents | PDF.js for import and preview, DOCX and JSZip for document paths, and an application-owned LaTeX template compiled by bundled pdfLaTeX. |
| Tests | Vitest for domain and workbench contracts, and Playwright for Electron and installed-app flows. |

`src/main/` owns privileged behavior, `src/preload/` owns the renderer bridge, `src/shared/` holds contracts, and `src/renderer/` holds the UI. `tests/` covers contracts and `tests/electron/` covers desktop behavior. `scripts/` contains build and verification tools. `resources/` holds the template, licenses, icon, and compiler lockfile. `prototypes/cv-tailor-ui/` is a separate npm workspace for design evidence, not an installed package.

## Process boundaries

| Layer | Ownership | Entry points |
| --- | --- | --- |
| Renderer | Four pages, user input, review state, and local display state. No Node or filesystem access. | [`src/renderer/main.tsx`](../src/renderer/main.tsx), [`src/renderer/WorkbenchStart.tsx`](../src/renderer/WorkbenchStart.tsx) |
| Shared contracts | Zod schemas and types for records and the renderer-facing `WorkbenchAPI`. | [`src/shared/appearance.ts`](../src/shared/appearance.ts), [`src/shared/profile.ts`](../src/shared/profile.ts), [`src/shared/jobs.ts`](../src/shared/jobs.ts), [`src/shared/draft.ts`](../src/shared/draft.ts) |
| Preload | Exposes `window.workbench` with named methods through `contextBridge`; parses IPC inputs and results. | [`src/preload/index.ts`](../src/preload/index.ts) |
| Main | Checks the calling frame, registers IPC handlers, creates the workspace, and manages native and external operations. | [`src/main/index.ts`](../src/main/index.ts), [`src/main/workbench.ts`](../src/main/workbench.ts) |

The browser window has context isolation and sandboxing, with Node integration disabled. The main process rejects IPC calls from frames other than the expected main renderer frame and blocks navigation. A new renderer capability therefore needs a shared API method, a preload implementation, a trusted main handler, and application logic. The renderer has neither generic IPC nor direct disk access.

## Durable data and domain records

`createWorkbench` in [`src/main/workbench.ts`](../src/main/workbench.ts) opens `workbench.sqlite` under Electron's per-user `userData` directory, enables WAL, creates tables, and runs forward migrations. The same module implements most storage operations; there is no separate repository layer. Stored JSON is parsed against shared schemas on read. The schema includes these groups:

| Group | Tables and purpose |
| --- | --- |
| Configuration | `settings` holds the exact Pi provider, model, and thinking level. `schema_migrations` tracks upgrades. The upgrade deletes the former CV Tailor OpenRouter ciphertext from `encrypted_credentials` and the retired `faithfulness-check` settings row; Pi owns its credentials outside this database. A legacy user-provided Tavily key may remain in Electron device encryption in a private sibling of `userData`, not workspace SQLite or backups. Settings checks only whether that encrypted legacy file exists and, when present, offers explicit confirmed local removal; there is no reveal, copy, replacement, save, or search action. Failed inspection is distinct from absence, and upgrades/backups leave the file untouched. The retired credential is never decrypted or sent to a provider. |
| Profile | `profile_contact`, `profile_skills`, `profile_entries`, `profile_experience`, `profile_projects`, `evidence_revisions`, and `profile_import_provenance` hold career facts and source history. Upload proposals remain temporary until an atomic reviewed apply. AI results are checked against application-issued source passages and supported local facts before replacing the local proposal set; stale merges keep the review token for explicit rebase until discard or expiry. |
| Jobs | `jobs` holds saved job records, including source snapshots and accepted posting revisions. |
| Model work | `outbound_consents`, `posting_analysis_cache`, `analysis_run_state`, `analysis_attempts`, `provider_attempt_outcomes`, `generation_recovery`, `generation_recovery_extensions`, and the SQLite graph checkpointer track authorization, work, and recovery. |
| CV review | `draft_revisions`, `regeneration_proposals`, and `document_fit_reports` hold the draft, replacement proposals, and page-fit results. |

The backend job-deletion contract is available through named preview and execute IPC methods. It fingerprints selected jobs and their related rows, refuses stale or busy selections, and deletes job-owned work in one SQLite transaction. `outbound_consents.job_id` binds newly accepted consent to its job, even before analysis starts. Migration backfills older consent only when surviving recovery, cache, or current analysis state links its run to a job. Older superseded failed or cancelled analysis and regeneration runs can have no surviving job link. Their consent, attempt, outcome, extension, or checkpoint rows remain in place when ownership cannot be proven. Run-linked attempts and graph checkpoints use the run ID collected before their ownership links are removed. In-memory authorization is revoked after commit. Profile evidence, other jobs, older backups and exported files are not deletion targets. [`SavedJobs.tsx`](../src/renderer/SavedJobs.tsx) owns selection, preview and confirmation state. [`main.tsx`](../src/renderer/main.tsx) refreshes jobs and shortcuts after commit, clears a deleted active selection, and rejects an older pending job-open response. The D2 visible flow and D3 installed acceptance status are recorded in [spec 72](validation/spec-72-implementation.md).

A **profile** contains source facts. A **saved job** holds the target posting. A **draft** is a version of the tailored CV with evidence citations; it is not the profile. An imported **posting source snapshot** remains distinct from the person's accepted **working posting**. `src/shared/profile.ts`, `experience.ts`, `jobs.ts`, `posting-import.ts`, `draft.ts`, and `document.ts` define these record shapes. A profile edit records an evidence revision, so a draft can detect changed cited facts.

## External input and model requests

The main process applies [`src/shared/job-source-policy.ts`](../src/shared/job-source-policy.ts) before automatic source access and again at trusted research and write boundaries. Generic/direct Lever fetch, save and refresh are paused; only the separate exact named Postings API path is allowed after explicit personal-local opt-in and app-held review. LinkedIn and Indeed direct or temporary reads, indexed search, search fallback and candidate rereads remain paused while source rights remain unresolved. Indeed classification uses a bounded list of reviewed country domains with DNS-label boundaries, including `indeed.co.uk` and `indeed.com.au`; it does not classify arbitrary lookalikes. The same decision covers captured research identities before review, outgoing preview and model dispatch, plus submitted and final URLs on import and refresh. Pauses run before DNS, HTTP, Tavily usage checks or persistence. The named Greenhouse and Lever API routes use a main-held, ten-minute volatile attempt/candidate and one-time review token. The #112 Wuzzuf candidate uses the same review/save boundary but a source-specific exact public-page adapter: one `wuzzuf.net/jobs/p/...` HTTPS URL, public DNS pinning, no redirects, bounded bytes/deadline/worker, and no credentials, cookies, retries, or linked requests. For identity-less `JobPosting` data, a unique canonical URL must match the selected URL and independently visible title and employer must match; exactly one role and complete description text visibly present on the page are required. The named Wuzzuf route stays disabled unless trusted main finds the owner's versioned policy file at `appData/CV Tailor Personal Local Policy/wuzzuf-personal-local.json` and matches its SHA-256 fingerprint of the canonical physical installation root. Packaged installs bind to the executable's directory; unpacked runs bind to the app root above `out/main`. The file stores the fingerprint, not the path or username. Thus two installs sharing appData cannot reuse one another's authorization; in-place upgrades keep their location, while moving an install requires owner re-authorization. It then still requires a distinct per-run notice/opt-in. The file is outside userData and workspace backups, is never created by the app, and malformed, linked, oversized, mismatched or absent files fail closed. This route remains separate from generic temporary research. A Save transaction rechecks installation enablement, verifies the reviewed attempt, and writes the accepted working posting, source snapshot and initial revision atomically; source text and user corrections remain distinct. Review and read also invalidate a held Wuzzuf attempt if its per-install policy is revoked. Duplicate, stale, declined, cancelled, incomplete and expired candidates do not enter workspace storage. Accepted records follow normal backup and explicit job-deletion behavior; backup artifacts are not silently rewritten. Manual paste and edits, saved-job reads, backups and restore bypass source-read policy. Explicit Open original actions open the user's browser and are never automatic. Other public hosts keep their current individual route behavior, which is not rights approval. Historical saved jobs, snapshots, revisions, drafts, approvals, backups and exports remain unchanged and available for tailoring. The pause does not claim that source use is unlawful or authorize deletion. Issue 104 still owns the generic/direct pause.

The former public HTTPS Lever adapter remains in [`src/main/safe-posting-fetch.ts`](../src/main/safe-posting-fetch.ts), but the shared policy refuses it before DNS. Lever's separate named API route uses `api.lever.co` only after opt-in and passes bounded fake tests for exact host/ID, DNS, redirect refusal, response size, explicit retry after a socket failure, and a two-second extraction deadline. EU Lever and generic/direct Lever remain paused. The direct-source route uses [`src/shared/job-research.ts`](../src/shared/job-research.ts) and [`src/main/job-research-fetch.ts`](../src/main/job-research-fetch.ts); its adapter checks policy before DNS, validates and pins public addresses, bounds redirects and response size, then extracts inert text in a worker. For an enabled source, a direct capture can transfer source identity and findings into one app-held temporary research session without another GET. The handoff is single-use; cancellation, expiry, source change and app close discard captured text. Fetch never invokes a model. Main holds volatile research sessions. Indexed search has been retired: the public research search API returns a manual-paste outcome without reading Settings credentials or dispatching any provider request, including for generic hosts. Any indexed-snippet or indexed-role-claim records mentioned in older fixtures/reports describe legacy behavior, not sources fetched by the current backend. A legacy encrypted Tavily key is dormant. Settings offers only explicit confirmed local removal while the file exists; absent keys produce no search UI. No migration or backup operation silently deletes the device-encrypted file. A reviewed full or provisional role selection must pass the same source policy before outgoing preview or Pi dispatch. Source text, snippets, authorization and Pi results stay out of jobs, cache, drafts, recovery and backups. Temporary analysis cannot generate or export a CV. This development branch has no installed-app or real-provider proof; see [Stage D validation](validation/universal-research-stage-d.md).

Before model work, [`src/shared/outbound-consent.ts`](../src/shared/outbound-consent.ts) constructs a minimized, scoped payload from the current posting and profile. [`src/main/workbench.ts`](../src/main/workbench.ts) binds authorization to a run and scope hash. Accepting a preview alone does not send the request. `startAnalysis` checks the current authorization before loading compatible cached data or calling the provider, and refuses a second analysis while a job operation is active. Draft generation requires the analysis and authorization for that run; a prior cached result is not permission to generate again.

[`src/main/pi-model.ts`](../src/main/pi-model.ts) resolves the selected physical chat model against Pi's registry and checks local authentication and supported thinking before dispatch. [`src/main/pi-workbench-dispatcher.ts`](../src/main/pi-workbench-dispatcher.ts) serializes run-authorized requests, sends each task's bounded JSON Schema as a system instruction, validates the response and output size, and records physical attempts. It sends no tools, loads no project instructions or extensions, and makes no automatic provider retry. A locally configured but expired credential can still fail at the provider. Pi and providers enforce their own quotas and context limits; CV Tailor keeps storage and file safety limits but has no local daily or per-run model quota. [`src/main/source-linked-generation.ts`](../src/main/source-linked-generation.ts) uses LangGraph to select evidence and produce structured, cited wording. New experience and project descriptions carry explicit paragraph-format metadata and must be one paragraph of at most 60 words. Drafts without that metadata retain bullet rendering and their released canonical JSON hashes, even when multiple old items share a parent. The generator rejects missing or foreign citations and malformed paragraphs; post-generation factual and keyword repairs must also satisfy the same final paragraph shape after local identifier restoration. Recovery snapshots from earlier prompt and optional-review contracts (versions 1, 2 and 3) remain backup-readable but cannot dispatch under old consent. New version-4 snapshots contain no faithfulness preference. [`src/main/sqlite-checkpoint.ts`](../src/main/sqlite-checkpoint.ts) stores graph checkpoints. The model supplies content, not executable LaTeX or authority to change profile facts. Repair prompts minimize locally restored identifiers again before dispatch.

## Review, export, and backup

The draft's citations carry evidence identities and revisions. Paragraph-format metadata travels from each generated experience or project item into the canonical document and stays per review item in mixed same-parent groups. [`src/main/factual-verification.ts`](../src/main/factual-verification.ts), [`src/main/workbench.ts`](../src/main/workbench.ts), and [`src/shared/document.ts`](../src/shared/document.ts) connect factual checks, a canonical document, page-fit measurements, and approval. Approval is tied to current content and review state. Edits and accepted cuts require a fresh check and approval before export. Automated checks cannot establish semantic truth; the person reviews the wording and sources.

The PDF uses the application-owned Letter/Lato template under [`resources/cv-template/`](../resources/cv-template/) and a bundled local pdfLaTeX toolchain. [`src/main/latex-compiler.ts`](../src/main/latex-compiler.ts) compiles in a disposable directory with bounded execution and no shell escape. [`src/main/pdf-document.ts`](../src/main/pdf-document.ts) measures the actual compiled PDF. [`src/main/docx-export.ts`](../src/main/docx-export.ts) creates an editable Word document from the same canonical content; Word pagination can differ from the PDF.

Profile PDF and DOCX imports extract text in bounded workers and produce proposals for explicit review. The same importer builds a complete ordered source-evidence document from readable PDF lines or DOCX paragraphs, preserving app-issued page and passage references and paragraph-local hyperlinks. AI-assisted extraction is the primary route, with local review available without Pi. A minimized source-text preview freezes the selected Pi provider, model and thinking level; explicit one-run consent is required before dispatch. The validator resolves citations only against the captured source-evidence document, checks exact source support and parent ordering, and assigns persistent proposal identities in the app. A source unit authenticates a text span, not semantic record ownership: units with multiple role headings cannot support AI record or nested-fact assignments, and multiple skill headings cannot justify new classifications or corrections. Rejected AI output leaves the original local review intact. Profile JSON exchange is a separate replacement path. [`src/main/workspace-backup.ts`](../src/main/workspace-backup.ts) validates backup data; restore previews replacement and makes a safety copy. Backup excludes credentials, discards legacy OpenRouter and faithfulness settings on restore, and does not restore authorization for cloud work. The renderer's `WorkbenchStart` implements the user-facing order.

## Invariants

- Shared contracts define record shapes. IPC, network, file, and provider boundaries validate external input.
- Consent binds to the operation and current source revisions. A cache hit does not waive new-run authorization.
- The dispatcher verifies frozen Pi model and effort plus current run consent before each physical provider call. Received malformed output terminates the saved generation checkpoint without keeping model wording or offering an uncertain replay; truly interrupted runs retain explicit recovery. Recovery snapshots from older prompt or optional-review contracts cannot resume under their earlier authorization, including interrupted Pi runs. Historical semantic-unsupported findings remain blocking on saved drafts.
- Posting source snapshots, accepted posting revisions, profile evidence, and draft wording remain distinct. Posting keywords are not career facts. Source-policy pauses do not alter historical records or backups. Unaccepted retrieval remains volatile; named Greenhouse and candidate Wuzzuf Saves are separate explicit reviewed actions and never authorize a model run. Wuzzuf Save uses only its exact Wuzzuf page route; generic Wuzzuf research stays temporary/non-saveable, and its accepted maintainer risk decision is not publisher permission. LinkedIn and Indeed remain paused; #113 Pi extraction remains independently consented and out of scope. Explicit manual paste is a separate user-authored save action.
- The app-owned canonical document, citation checks, PDF page measurement, and approval guard constrain export.
- The [frontend design contract](../design%20system/README.md) governs renderer changes. Prototype state is design evidence, not production data or a supported feature.
