# Egypt/MENA job discovery: compliant acquisition options

**Research date:** 2026-10-21
**Scope:** First-release job discovery for CV Tailor (local Windows Electron + TypeScript; OpenRouter). Primary/official sources only. This is a source review, not legal advice or a guarantee of market coverage. Access terms can change; recheck before shipping any connector.

## Recommendation

Build discovery as a phased workspace around **single-link job-posting import with manual text fallback**. The user-requested primary experience is **paste posting URL → fetch/extract details → review/edit → save**, without copying the description or entering title/company when extraction succeeds. For supported sources with a permitted access basis, use documented posting endpoints or local structured-data/readable-HTML parsing; retain source text/provenance and only populate details actually present. Preserve the existing paste-text route for restricted, login-required, JavaScript-only, or incomplete pages. Open the source link in the system browser for current details and applications. This is user-directed capture of one known posting, distinct from multi-board discovery, and does not treat a public webpage or robots.txt as a reuse license.

The single-link flow is a confirmed **standalone Phase 1a** requirement in [the adoption plan, §5 B1](ai-job-search-adoption-plan.md#b1-import-a-single-posting-from-its-link--early-release-requirement), independent of new fit/ranking, cover letters, tracking, or multi-board discovery. The user confirmed explicit fetch/refresh and save; temporary unsaved previews; local extraction without website scripts, model calls, or paid scrapers; reviewed sources only, with no speculative fetch of unknown sites; incomplete-content/material-conflict resolution; and manual fallback. Preserve source snapshots separately from accepted working postings/revisions, compare refreshes without overwriting edits, and stale current targeting when requirements change. Raise the existing 30,000-character storage limit within tested ceilings, while gating oversized model analysis separately; never truncate silently. Follow only bounded validated supported HTTPS redirects and show pasted/final sources. These decisions authorize documentation only. They do not change the source-specific findings below or establish previously unverified scraping permissions.

Add **opt-in employer ATS public-feed connectors** next, starting with Greenhouse, Lever and Ashby. These official APIs expose published employer-board postings without a general board-wide search index. Make the user select/enter the employer board identifier (or discover it only from an employer-provided careers URL); show source and retrieval time, and always link to the employer's original posting. A connector retrieves only participating employers' feeds, not all Egypt/MENA vacancies.

Treat WUZZUF, Forasna, Bayt and GulfTalent as **manual-link/paste sources until each grants a documented API/feed license or written permission**. Do not scrape their pages, automate browser sessions, use account cookies, rely on unofficial endpoints, or infer authorization from robots.txt. Do not ship LinkedIn scraping; its official terms prohibit scraping/automated access and its APIs require approved access. Consider a licensed job-data supplier only after evaluating actual Egypt/MENA coverage, refresh/expiration behavior, language, downstream storage/display rights, attribution, price and data-protection terms.

Do not promise full-board coverage. Position connectors as a collection of approved/public employer feeds plus user-supplied postings.

### What “public API” does and does not establish

For Greenhouse, Lever and Ashby, the cited official docs establish a documented public read surface for a particular employer's published jobs. They do **not** establish permission to build a commercial cross-board index, store indefinitely, redistribute full descriptions, or use an endpoint at any volume. Before enabling broad sync, verify applicable terms, permitted caching/display, attribution, rate limits, user-agent/contact requirements, retention/deletion, and employer/feed-owner expectations. A website being reachable, an endpoint being technically callable, or robots.txt allowing a crawler is not affirmative contractual authorization.

## Language, location and eligibility constraints

- Egypt/MENA postings can be Arabic, English, bilingual, or use mixed scripts and transliteration. Preserve original text and language metadata; do not overwrite it with a machine translation. Search/matching can offer Arabic and English query variants, while making clear that transliteration and mixed-language recall are imperfect.
- A posting location is not a work-rights determination. Collect location/work arrangement and eligibility requirements when present, but represent missing/ambiguous sponsorship, visa, nationality, language, and relocation conditions as **unknown** and ask the user to assess them. Do not infer a user's eligibility or that “remote” permits work from Egypt or another country.
- Employer feeds differ in structured location/language fields; free-text descriptions remain necessary. Normalize only alongside the original source value. Handle date/time-zone ambiguity and stale/closed postings conservatively; a successful fetch does not prove the role is still open.
- MENA is not one labor market or legal regime. Validate countries and supported languages separately; do not represent a small Egypt sample as MENA-wide coverage.

## Suggested phased delivery

1. **Standalone capture foundation and link import:** Add **Import from link** after the relevant job/backup migrations and intake prototype. Explicitly fetch one URL only if its host/path matches reviewed source rules; use a permitted detail endpoint, structured posting data, or supported static HTML. Unknown websites receive fallback without a speculative page fetch. No website scripts, paid scraper, browser cookies, or automatic model requests. Preview title/company/full description and optional explicit fields; block save on unresolved essential incompleteness or material conflicts. Keep previews off disk until explicit Save and warn before discarding edits. Save complete source snapshots separately from accepted working postings/revisions. Compare old source/current edits/new source on refresh; never auto-merge or overwrite, and stale targeting for accepted changed requirements. Define larger tested text ceilings and separate analysis-context gating; preserve full source rather than silently shorten it. Validate bounded redirects/DNS/public connection destinations and show pasted/final links. Cancellation/late responses never mutate saved data. Offer **Open original posting** and **Paste posting text instead** for restricted/unsupported/JavaScript-only pages. Verify legacy backups, full-text/source separation, conflict/limit handling, no speculative or background requests, and offline reopen. No access-control bypass or universal job-board support claim.
2. **Employer-feed pilot:** Implement one ATS connector behind an explicit user action and board identifier. Prove read-only retrieval, schema parsing, link provenance, timeouts, duplicate handling, closed/unreachable states, bounded refresh and actual Egypt/MENA sample coverage. Pilot the three APIs independently; don't generalize one adapter's rights/behavior to another.
3. **Permissioned aggregators:** Seek written terms or a licensed supplier for named regional boards. Document ingestion/display/caching scope, attribution, retention, takedown/contact route, costs and supported geographies/languages before committing to an integration. Keep manual capture as fallback.
4. **Optional FreeHire spike:** Audit API terms/license and upstream connector dependencies; query facets and sample Egypt/MENA listings, source URLs, freshness/duplicates, and missing work-eligibility metadata. Ship only if coverage and data rights meet an explicit acceptance bar.

## Validation spikes / questions to resolve

- Request written API/feed or partner permission from WUZZUF, Forasna, Bayt and GulfTalent; ask whether a local desktop app can store/display snippets/full descriptions, attribution requirements, and whether commercial use is allowed.
- Confirm with Greenhouse, Lever and Ashby (or their published terms/support) allowed third-party read/caching use, rate limits, data retention/deletion and attribution, beyond the technical API documentation.
- For FreeHire, check current terms/license, source-level licenses/agreements and whether redistribution/cache is permitted; test Egypt and at least one Gulf-country query, Arabic/English mix, freshness and original URL integrity.
- Validate single-link extraction on a permitted-source sample: documented detail data, structured `JobPosting` data, static HTML, missing/conflicting fields, multiple postings, closed roles, JavaScript-only pages, login/access blocks, unsafe redirects and timeouts. Verify unknown sources trigger no page fetch, paste/reopen triggers no request, previews remain non-persisted, and local edits survive compared refresh. Measure complete-description extraction and user correction effort; publish a supported-source matrix rather than promising arbitrary-link success.
- Establish tested download/decompression/parsing/storage ceilings and a larger supported text limit than today's 30,000 characters. Verify full-text storage independent of provider context, explicit analysis gating, preserved source on reviewed shortening, and no silent truncation. These technical ceilings/source entries need feasibility evidence before implementation; no live source validation was performed during the design interview.
- Define an acceptance sample by country, language, occupation and source, with a measured stale/duplicate/empty-feed rate. Do not launch an “all Egypt jobs” or “all MENA jobs” claim.
- Confirm product expectations for default country list, English/Arabic UI vs posting-language support, remote-work geography, and explicit handling of work authorization/sponsorship unknowns.
- Design privacy/data lifecycle for saved job text (including potentially personal contact information embedded in postings), user-controlled deletion and OpenRouter data exposure; ATS feed text remains untrusted external input.
