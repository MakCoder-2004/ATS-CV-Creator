# Job-posting source access and retention gates

**Research date:** 2026-10-26. **Purpose:** Set source-specific gates for automatic retrieval and saved job postings. This is documentary research, not legal advice or an authorization to fetch, display, use, or retain any source content.

## Decision

No reviewed source has both an authorized automatic retrieval route and established rights for durable display/use and retention in CV Tailor. Do not enable automatic saving or refresh for any newly fetched source based on this report. LinkedIn is **BLOCKED**. Indeed is **BLOCKED**. Greenhouse and Lever are **INCONCLUSIVE** because their official technical documentation describes public read routes but the reviewed official materials do not settle this app's downstream display, use, storage, and deletion rights.

A reachable URL, public endpoint, or user's Save action does not grant reuse rights. Manual paste is a separate user-authored route, not automatic source capture and not evidence that fetched wording may be saved.

## Status meanings

- **ENABLED** means the reviewed official terms and documentation support the stated automatic route and its specific downstream use and retention.
- **BLOCKED** means reviewed official terms rule out the proposed route or no permitted route is documented for this use.
- **INCONCLUSIVE** means a technical route exists or may exist, but official evidence reviewed here does not resolve authority for this app's use. Treat it as unavailable until the gate is resolved.

The automatic retrieval verdict is about permission and approved scope, not whether an HTTP request might return a response. The separate save/retention verdict covers keeping source wording as a posting source snapshot and displaying or using that wording in a saved job and CV-tailoring workflow.

### What the technical documents do and do not establish

Greenhouse and Lever document narrowly addressable public reads. Their endpoint shape, response fields, and unauthenticated access do not establish a license for storing a captured posting or using its text as durable CV-tailoring input. Conversely, the absence of a retention clause in these API documents is not permission for indefinite storage. The terms found for LinkedIn and Indeed are more explicit: LinkedIn requires approval and restricts scraping and data storage; Indeed requires an approved API integration and disallows scraping and permanent copies outside an approved/documented purpose.

No claims here rely on search-result summaries. The cited official pages were reviewed directly on 2026-10-26. Page revision dates are included where the pages state them. No live posting URL, login, cookie, authenticated session, or posting body was accessed.

## Manual paste is separate

The current app accepts manually entered job-posting text and saves it on device. That path is a user's own entry, not automatic source capture. Pasting does not make a source fetch permissible, prove the pasted text is authorized for any use, or turn an unaccepted fetched preview into a saved posting. Keep the two paths clearly distinguished in product copy and storage decisions.

## Conditions for any future accepted source

A source can move to **ENABLED** only after its exact official terms or written agreement cover the named route, selected-job scope, full-text retrieval, display to the user, use as input to CV tailoring, and storage in the workspace and backups. Record the applicable account, approval, API scope, permitted fields, frequency or rate limits, attribution, and any charges. Re-review if the integration, source terms, data use, or storage policy changes.

If a source passes that gate, each posting source snapshot must retain provenance separate from the user's working posting and corrections. Store the canonical source URL, provider and route, source posting ID, retrieval timestamp, source-reported update/publication dates when supplied, parser/version, and content hash. Display retrieval time and source identity. Refresh only on explicit user action through the same approved route. Never label captured text current solely because it was once fetched. Let users inspect captured wording against their working posting and accept or reject corrections without rewriting the snapshot.

Before enabling retention, define a source-specific expiration and deletion rule from the governing terms. A user's Save action is not a substitute for that rule. Deleting a saved job must remove its source snapshot, working posting, revisions, and associated derived data under the product's deletion behavior. Expiration, a source-owner request, a license ending, a source access revocation, or a correction that replaces source content must trigger the agreed deletion/update process. Define how deleted source text is removed from backups, including backup expiry or rewrite, restore behavior, and any legally required audit-only record. Keep only a minimal tombstone or deletion receipt if the agreement permits it; do not preserve deleted posting text as “history” by default. Retention duration, backup treatment, and any exception must be explicit before implementation.

## Product gate and current UI conflict

Until one source passes both gates, automatic capture may be reviewed only as temporary content if separate temporary-access and cache rules authorize it. No new automatic capture may be saved or refreshed as a job posting. If all sources remain unresolved, the product must say that saved automatic intake is unavailable and offer manual paste. Do not silently enable a source based on successful fetch, public reachability, or consent to save.

The current [Saved jobs UI](../../src/renderer/SavedJobs.tsx) says “LinkedIn, Indeed, Lever and other public HTTPS job links may work” and allows a direct-fetch path for non-Lever sources. That copy suggests general availability and conflicts with these rights gates. The current [workflow guide](../workflows.md) says new non-Lever fetches are temporary and cannot be saved, while Lever retains a save/refresh path. That storage safeguard is consistent with a closed gate, but the UI's source-availability claim is not. This research task makes no code or copy change. Update the UI claim before any automatic source is enabled, and do not treat the existing Lever save path as rights approval.

## Evidence limits

This review covers the official sources linked above and prior project findings. It does not decide copyright, contract enforceability, or whether a particular user has rights to a pasted posting. It does not review every country-specific term, employer agreement, API contract, or downstream rightsholder. Obtain a specific written permission or agreement and product decision when the documents leave the question unresolved.
